# Pardes (פרדס), an Android app based on Zayit

Pardes is an Android 8.0+ (minSdk 26) app based on [Zayit](https://github.com/kdroidFilter/Zayit), the open-source (AGPL-3.0) desktop app by Elie (Elyahou) Gambache. He did not make Pardes, is not responsible for it and does not support it, so please don't report its problems to him or to the Zayit project. It was called "Zayit for Android (unofficial port)" until October 2026; at his request it now has its own name and icon (the word פרדס in gold on olive green) and its own application id, `io.github.efrul.pardes`. It reuses the desktop's `SeforimLibrary` core and dao code unchanged, and redraws the UI in Jetpack Compose to look and behave like the desktop "Islands" layout on phones (down to the 3" Unihertz Jelly Star) and tablets. See [DESIGN.md](DESIGN.md) for the screen-by-screen mapping.

![Pardes, an Android app based on Zayit: home, search, reader, dark mode, tools, year cycle, Jelly Star, home-screen widgets, tablet](docs/release/overview.png)

The images are in [docs/release/](docs/release/).

Site: https://efrul.github.io/Pardes/ (source in [site/](site/), deployed to GitHub Pages by `.github/workflows/android-site.yml` on every push that changes it). Four pages for Android and desktop: the home page, a guide (installing, and the ways to bring in the library), every download, and the changelogs ([CHANGELOG.md](CHANGELOG.md) and [desktop/CHANGELOG.md](../desktop/CHANGELOG.md)). They read the versions and files from `releases.json` and `downloads.json`, written at each deploy; only the downloads page also asks the GitHub API, for the current download count. It also offers the transfer scripts.

## Build

This is a standalone Gradle build. It compiles SeforimLibrary (core, dao, search, delta-updater, and generator-common's `PatchTables.kt`) from the repository's `../SeforimLibrary` submodule, at the commit desktop Zayit 0.6.11 builds with (4f07145): desktop and Android build from the same checkout. From the rest of the repository it reads `../icons` (the search telescope), `../LICENSE` (bundled as the app's licence text) and the Temple widget's `temple_count.txt` (desktop's `files/`, copied into the assets). Desktop's htmlparser and user-settings schema are vendored, as 0.6.10 has them, in `app/src/androidMain/htmlparser` and `app/src/androidMain/sqldelight-user`.

```bash
git submodule update --init SeforimLibrary   # once, after cloning (from the repository's root)
cd androidApp
echo "sdk.dir=/path/to/android-sdk" > local.properties
./gradlew :app:assembleRelease    # R8-minified APK (~36 MB, native libraries compressed: ONNX Runtime for the semantic search, 14 MB, then fonts and wallpapers), signed with the shared debug key
./gradlew :app:assembleDebug      # unminified, debuggable
```

Requirements: JDK 21+ (`lucene-android/` compiles against lucene-core's Java 21 class files, which javac 17 cannot read), Android SDK 36. The JBR bundled with Android Studio is a JDK 21. Building on Windows is covered in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#working-on-windows).

Both build types are signed with the project's debug key, `debug.keystore` (CN=Pardes Android Debug), so builds from different machines install over each other. Published releases are signed with Pardes's own key instead (below), so a release and a local build cannot be installed over each other, and only releases update themselves from within the app.

**CI release.** `.github/workflows/android-release.yml` runs the same release build on GitHub Actions (JDK 21, SDK 36). It runs only by hand, never on a push: Actions › Android release › Run workflow, on `main`. It signs the APK with Pardes's own key, which only the repository's secrets hold, and stops unless the APK carries that key's certificate. It also stops unless `lucene-android/check-min-api.sh` reports nothing above API 26 and 0 missing references, then publishes a release marked Latest (so it shows on the repository page), tagged `android-<versionName>-<run number>`, with the APK (`pardes-android-0.2.0-7.apk`), its complete source including the SeforimLibrary submodule (`pardes-android-0.2.0-7-source.tar.gz`, since GitHub's own source archives leave submodules out), `push-desktop-library-windows.zip` (the `.ps1` with its `.cmd` launcher) and `push-desktop-library.sh`. `versionName` in `app/build.gradle.kts` sets the tag. The release notes say what is new from that version's section of [CHANGELOG.md](CHANGELOG.md) (`## <versionName> · <date>`), and the run stops before the build when there is none: write it, and raise `versionName` and `versionCode`, before a release. The app reads these releases to update itself ([below](#updating-the-app)): it offers a release only when its `versionName` is higher than the installed one, so keep the tag and the APK's name as they are, and raise `versionName` (digits and dots only, e.g. `0.4.0`) for every release.

## Getting a library onto the device

- **On a phone:** the first-run flow downloads the same release that desktop uses (about 5.5 GB). It downloads and extracts in one streamed pass, so the compressed bundle is never stored, and it resumes after a dropped connection. It keeps everything desktop installs, search indexes included (13.06 GB unpacked: `seforim.db` 8.02 GB, `seforim.db.lucene/` 4.95 GB, `lexical.db` 81 MB…), and needs about 14.1 GB free.
- **From a computer with desktop Zayit:** `tools/push-desktop-library.sh` (Linux/macOS) or `tools/push-desktop-library.ps1` (Windows; double-click `push-desktop-library.cmd` next to it, which runs it with the execution policy bypassed and keeps the window open; the site and releases offer both in `push-desktop-library-windows.zip`) copies the installed desktop library over adb and makes it writable for the app, with no download and no root. When that library has Pardes's semantic pack (`pardes-model/` and `pardes.vec.lucene/`, from Pardes for desktop), it is copied too, 2.8 GB more. The `.sh` streams each file straight into place, so the phone needs the library's size plus 0.5 GB free (about 13.6 GB). adb on Windows cannot stream binary data that way, so the `.ps1` passes each file through a staging folder on the phone, a file over 2 GiB in pieces of that size, and needs 2 GiB on top, about 15.7 GB. `--sdcard` (`-SdCard`) copies to the memory card instead, seforim.db in chunks on a FAT32 card, and then removes a library in the phone's storage, so that the app keeps one. It does so only for Pardes 0.3.0 or later (versionCode 2), which can open a library on the card. With `-SdCard` the `.ps1` still stages each file on the phone, so the phone needs about 2.2 GB free besides the card's 13.6 GB. Both can replace a library the app downloaded itself. `--with-notes` (`-WithNotes` in the `.ps1`) also brings the desktop notes and highlights; `--dry-run` (`-DryRun`) prints the adb commands. They need adb: on PATH, in the Android SDK, or Google's Platform-Tools unzipped next to the script. The `.sh` looks only in `platform-tools/` beside it; the `.ps1` also finds it up to three folders deeper, since Explorer's "Extract All" nests it one level down.
- **From a computer, as a file:** [Zayit Export](https://github.com/efrul/zayit-export) (Windows) packs the installed desktop library into the bundle that the offline install reads (`zayit-library-<edition>.tar.zst`, or `.partNN` pieces with a manifest, `release_info.txt` and `library_size.txt` first), and can send it straight to a phone in file-transfer (MTP) mode, with no adb.
- **Offline:** choose the `.part` files, a `.tar.zst`, or a ready `seforim.db` with the system file picker. A bare `seforim.db` brings no search index, so search stays off until a full install. When the phone lacks room for the full library, the first-run disk step leads on to this install from files only ("המשך להתקנה מקבצים", the download disabled). That install asks for the room the bundle's `library_size.txt` declares plus 1 GiB; a bundle without it, or with it after the library's files, is taken to need the full library's room.
- **A small library:** [Zayit Subset](https://github.com/efrul/zayit-subset) (Windows) builds a library of chosen books, with their commentaries and filtered search indexes, in the desktop layout; the app opens it as is. Its "העברה לטלפון…" button runs its own bundled copy of this folder's `push-desktop-library.ps1` with `-Source` and `-Serial` (a copy that reaches Pardes from Zayit Subset 1.0.1 on; 1.0.0 bundles one that looks for the app's former id), and Zayit Export packs a small library when Zayit Subset has switched desktop Zayit to it (`SEFORIMAPP_DATABASE_PATH`). It can also be copied by hand in File Explorer: once the app has started (it creates `files/library/` at its first start), the folder's contents go to `Android/data/io.github.efrul.pardes/files/library/` in the phone's internal storage, and the first-run flow finds the library after the licence step. Files and folders that MTP writes there belong to the media provider (mode 2770/0664, label `s0:c512,c768`), and still the app reads and writes them: on the Jelly Star a process with the app's uid and groups (no `ext_data_rw`) could, through the default ACL that Android puts on the app's folder, and on the emulator the app opened, searched and wrote such a library (2026-10-18). Windows lists a memory card first, as a storage of its own.
- **Updating without a network:** Settings › ניהול נתונים › "עדכון מקבצים" or "עדכון מתיקייה". Pick the two files of an incremental update from the SeforimLibrary release page, `patch-v<from>-v<to>.db.zst` and its `.manifest.json` (several steps chain by their content hashes); an incremental update needs Android 11 or later, and on Android 8 to 10 the app refuses it and points to a full update. Or pick every `.part` file of a full release, with its manifest. A full update leaves the working library in place until the new one has been read to the end and checked, when there is room for both. It deletes the old one first only when that makes the room, and otherwise stops before deleting anything. A bundle packed by a tool may start with `release_info.txt` and `library_size.txt` (`library=<bytes unpacked>`): an edition too old for the app is then refused, and the free space checked, with nothing deleted.
- **For development:** `tools/make_subset_db.sh` builds a small `seforim.db` (Bereshit, Berakhot and Mishnah Berakhot, with their commentaries) from a full database. Push it to `/sdcard/Android/data/io.github.efrul.pardes/files/seforim.db`; the app adopts it on start.

## The library on a memory card

A library of 13 GB fits on a memory card (an SD card that Android mounts as portable storage). Pardes keeps it in its own folder on the card, `Android/data/io.github.efrul.pardes/files/library/`, which needs no storage permission. Android deletes that folder when the app is uninstalled, as it does on the phone.

- **Choosing:** with a card in the device, the first-run disk step lists the phone and the card with their free space.
- **Moving:** Settings › ניהול נתונים › "מיקום הספרייה" moves the library between the phone and the card. The copy runs in the background with a notification. Each file is checked: its size, and a checksum of its end, read back after the app asks Android to drop the copy's cached pages. This makes sure the copy is complete. It can also reveal a fake-capacity card, which loses the end of what is written to it, but it cannot promise to: Android may still serve the read from its cache. The old copy is deleted only once the new one is in place, and then the app starts again. A library found in the other place, for example one copied onto the card from a computer, can be switched to or deleted there.
- **Card taken out:** the app asks for the card and opens by itself once the card is back. It never downloads the library again on its own. Taking the card out while the app runs closes the library first and starts the app on that screen.
- **FAT32 cards** (Android formats cards of 32 GB and less that way) take no file of 4 GB or more, and `seforim.db` is 8 GB. On such a card the database is kept in chunks, with SQLite's multiplex VFS layout: `seforim.db` (2 GiB less 64 KiB), then `seforim.db001`, `seforim.db002`… They are read through the app's own SQLite (requery sqlite-android, with the multiplex VFS built from `app/src/androidMain/cpp`), since Android's SQLite cannot read chunks. A split library takes full updates only; an incremental update needs exFAT (and Android 11). A card formatted as exFAT on a computer takes the database as one file.

## Updating the app

Pardes updates itself from within, as desktop Zayit does with its Nucleus updater (`app/.../update/`).

- **Finding a new version:** at every start (Settings › כללי › "בדוק עדכונים בכל הפעלה", on by default) and on "בדוק עדכונים" in Settings › כללי. It reads the GitHub API's 30 newest releases, or the site's `releases.json` when the API cannot be reached or that page holds no Android release (Pardes for desktop's releases share the list; the site itself reads every page). The newest release that is not a pre-release, with a `pardes-*.apk` and its sha256 digest, is offered when its `versionName` (from the tag) is higher than the installed one. What is new comes from the site's `changelog.md` (this folder's CHANGELOG.md), the sections between the two versions.
- **Telling the user:** once per new version, a snackbar ("גרסה X של פרדס זמינה", "פרטים"). While the version is known, the title bar has desktop's badge: a button on a tablet, a dot on the phone's overflow menu with "עדכון זמין" as its first item. Both open the update dialog: the version, the size, what is new, and "הורד והתקן" / "מאוחר יותר". Settings › כללי has desktop's banner at the top of the app card.
- **Downloading:** into the app's cache, with the library downloads' network code (it resumes after a dropped connection), in the foreground with a notification and a cancel action. Then the APK is checked: the sha256 that GitHub publishes for the asset, and that Android reads it as Pardes, of the offered version and not older, signed with the same certificate as the installed app. A file that fails is deleted and never installed.
- **Installing:** Android's PackageInstaller. The first time, Pardes needs Android's permission to install apps: "פתח הגדרות" opens "התקנת אפליקציות לא מוכרות", where the user turns on "לאפשר מהמקור הזה", and the install goes on when the user comes back. Pardes then replaces itself, usually without a further question (it holds `UPDATE_PACKAGES_WITHOUT_USER_ACTION`); when Android does ask, its confirmation opens, or waits in a notification ("המשך בהתקנה" opens it again). The library, the settings and (with "שמור מצב בין הפעלות") the tabs stay. Android ends the app at the end of the install; the new version says "פרדס עודכן לגרסה X" in a notification and once in the app. On Android 11 two things differ: turning the permission on restarts Pardes (Android 11 ends an app whose install permission changes), and when the user comes back, the new process opens the update dialog again and installs the checked APK by itself; and Android asks to confirm every update, since `UPDATE_PACKAGES_WITHOUT_USER_ACTION` exists only from Android 12. Android 8 to 10 also ask to confirm every update, but keep Pardes running when the permission is turned on (checked on 8.0).
- **Not while the library is busy:** an install ends the process. While the library is being installed, moved or updated, the download and the install are refused with a message (try again when it ends); a confirmation still waiting is withdrawn when such work starts, and the library work does not start while Android installs the update.
- **Development builds** (signed with the debug key) cannot take a release over them, so they look for no update; Settings › כללי says so. For testing, a development build reads `files/app-update-test-feed.json` in its private storage (releases.json's shape) instead of GitHub, and `files/app-update-test-changelog.md` for what is new; the feed's APK URL may be a `file:` URL inside the app's files. [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#testing-the-app-update) has the recipe.

## Structure

`app/src/androidMain/kotlin/io/github/kdroidfilter/seforimapp/android/`

| Folder | Contents |
|---|---|
| `update/` | Updating the app itself: the release list and changelog (`AppReleases`), the APK's package and certificate checks (`AppPackages`), the engine (`AppUpdater`: check, download, verify, PackageInstaller), its foreground service, notifications and receivers |
| `data/` | Library store and installer, `PragmaSafeDriver` (Android rejects row-returning PRAGMAs in `execute`), preferences, notes and highlights, history and favourites, zmanim and calendar logic for the tools, and the commentator grouping ported from desktop |
| `ui/shell/` | App frame: phone top bar or tablet tab strip, tabs, overlays, history and favourites screens |
| `ui/home/` | Home: logo, search field, catalog row, zmanim cards |
| `ui/reader/` | Book reader with the commentaries, targum, sources, notes and book-info panes; TOC and library drawer; long-press line actions |
| `search/semantic/` | Pardes desktop's semantic search (the model on ONNX Runtime, the vector index, the fusion with the search by words, and the pack's download, import and swap at start), as Android variants of desktop's files with their names |
| `search/` | The desktop 0.6.10 Lucene search on the library's prebuilt indexes: Android variants of the four desktop classes that use JDBC, MMapDirectory or `Path.of`, the desktop app files the search needs (vendored from 0.6.10: snippet sources, author names, reference parsing), and `SearchService`, which opens them. Since 0.6.1 the vendored files and `LuceneLookupSearchService` changed only by the 0.6.2 fixes 2126c238 and 90552dbc, `AcronymFrequencyCache` only for desktop's CLI (58e8beb5), and the engine by SeforimLibrary c3190c4 (the found line's range in a hit) |
| `ui/search/` | Full-text search screen (port of the desktop search results: paging, category/book tree with counts, base-books-only telescope) |
| `ui/settings/`, `ui/tools/`, `ui/onboarding/` | The desktop settings window, tools menu and first-run flow |

## Links

- `zayit://book/{bookId}/line/{lineId}` opens a passage (the same link as desktop's "copy link"). The scheme stays `zayit`: it is the format desktop Zayit and the library data use, not this app's name.
- `zayit://search/{url-encoded query}` opens a search (desktop's share link for a search tab). `zayit://search?q=…` works too.

## Known differences from desktop

The app follows desktop Zayit 0.6.11 screen by screen (0.6.1 until October 2026). [docs/PARITY.md](docs/PARITY.md) is the checklist of every difference found by comparing it with the real 0.6.1 sources, and records what each desktop release since then changed and what became of it here. What still differs on purpose:

- **Name and authorship:** The app is Pardes, with its own icon, wherever desktop says Zayit. Where desktop says who made the app (the welcome step, the settings header, About, the terms), Pardes says instead that it is based on Zayit by Elie (Elyahou) Gambache, who did not make it and is not responsible for it; his copyright, AGPL and §7b notices are kept, and About links Pardes's own source. Desktop's About text (its author on Zayit, in his first person) and the Rashi Amiti font (licensed to the Zayit app only) are left out.
- **Meaning-based (semantic) search:** Zayit's comes from a private package and is not included. Pardes has its own, the one of Pardes for desktop (Dicta's open model, [../SEMANTIC_SEARCH.md](../SEMANTIC_SEARCH.md)), with the same model and pack, on 64-bit devices (not Android Go ones, short of memory for the model): Settings › ניהול נתונים › "חיפוש לפי משמעות" downloads the pack (2 GB, about 3.3 GB free needed) or imports its files, and the transfer scripts copy it from a desktop library that has it. Without the pack the search finds the words, like the desktop community build. What differs from Pardes desktop: [docs/PARITY.md](docs/PARITY.md#pardes-desktops-semantic-search).
- **Google Drive backup:** left out, because desktop uses a desktop-only OAuth client. Backup to a file works.
- **Updating the app:** desktop's Nucleus updater can install a patch on close without asking. On Android the downloaded APK goes to Android's PackageInstaller; the first time the user must let Pardes install apps in Android's settings. Desktop always checks at start; Pardes has a setting to turn that off. Only published releases update themselves (development builds have another signing key).
- **Smart siddur:** the full template siddur is a private desktop package. Android implements its portable parts.
- **Verse quote links in the Talmud:** a private package of desktop's official builds (0.6.5), not included.
- **Tabs that no longer fit (tablets):** desktop 0.6.5 gathers them under an "עוד N" chip; the tablet strip here scrolls, keeping the shown tab in view, and the phone lists its tabs.
