# שירות המשוב של פרדס

Worker של Cloudflare עם מסד D1. הוא מקבל את חבילות המשוב שמשתמשים שולחים מפרדס למחשב: מהכרטיס "שליחת משוב" שבהגדרות ›
ניהול נתונים, ומהשליחה האוטומטית שהם מאשרים בשאלה שנפתחת בהפעלה. את החבילות הוא נותן למתחזק
([`pardes-semantic/feedback/fetch.py`](https://github.com/efrul/pardes-semantic/blob/main/feedback/fetch.py)), ומציג
לכולם באתר שלו את המספרים שהן מסתכמות בהם. את החיפושים עצמם רואה רק המתחזק. באתר אפשר גם להעלות חבילות ששמרו לקובץ. מבנה
החבילה מתואר ב־
[`pardes-semantic/feedback/README.md`](https://github.com/efrul/pardes-semantic/blob/main/feedback/README.md).

## מה נשמר, ומה לא

- כל חבילה נשמרת כמו שהגיעה (JSON): הציונים, החיפושים, הסימונים בצורת הדף, מזהה השולח האקראי, והגרסאות של פרדס ושל
  הספרייה.
- לא נשמרים כתובת ה־IP, ה־User-Agent או כל כותרת אחרת של הבקשה, ואין יומן בקשות (`observability` כבוי ב־`wrangler.toml`).
  הכתובת משמשת רק את מגבלת הקצב, בזיכרון של Cloudflare.
- משתמש שמבקש למחוק את מה ששלח (בכרטיס) מוחק את כל החבילות של מזהה השולח שלו. המחיקה נרשמת, כדי ש־`fetch.py` ימחק בהורדה
  הבאה גם את העותקים שכבר הורדו.
- מזהה השולח לא מוצג לאף אחד חוץ מהמתחזק: מי שיודע אותו יכול למחוק את מה שהשולח שלח. האתר לא מציג שום מזהה של שולח, וגם לא
  שם אותו בהורדות. בכתובת הציבורית שהאתר קורא, במקום המזהה יש כינוי: 12 הספרות הראשונות (הקסדצימליות) של SHA-256 של
  המזהה, שאי אפשר לחזור ממנו למזהה. הכינוי משמש את האתר רק כדי לספור כל שורה של שולח פעם אחת, וכמה שולחים יש.
- המילים שחיפשו והתוצאות שדורגו לא מוצגות לציבור: המשתמשים שלחו אותן כדי לשפר את פרדס, לא כדי שיתפרסמו. בכתובת הציבורית
  כל חיפוש (המילים והיקף החיפוש) וכל תוצאה שדורגה מופיעים רק כמזהה אטום: 12 הספרות הראשונות של HMAC-SHA-256 שלהם, במפתח
  שנגזר מ־`ADMIN_TOKEN`. אותו חיפוש מקבל אותו מזהה, ולכן האתר יכול לספור, אבל בלי המפתח אי אפשר לדעת מאילו מילים הוא, גם לא
  בניחוש. לא עוברים בה גם ההיקף (ספר, קטגוריה), המקום שדורג וכל שדה אחר שהשולח הוסיף. הסימונים בצורת הדף, מילים מהגמרא,
  עוברים כמו שהם.

## הכתובות

| בקשה | מה |
|---|---|
| `POST /v1/packages` | חבילה (JSON, עד 1,000,000 בתים) ← `201 {"id"}`. כך שולחת האפליקציה, וכך גם ההעלאה באתר |
| `DELETE /v1/senders/<id>` | כל מה שהשולח שלח ← `{"deleted"}` |
| `GET /v1/public/packages?after=<id>&limit=<n>` | לכולם: החבילות שאחרי המזהה, עד 50 בבקשה, והמחיקות. כל שולח (גם בתוך החבילה) מופיע בכינוי, ובמקום המילים של כל חיפוש ותוצאה מדורגת יש מזהה אטום (למעלה) |
| `GET /v1/packages?after=<id>&limit=<n>` | למתחזק: רשימת החבילות שאחרי המזהה, והמחיקות |
| `GET /v1/packages?bodies=1&after=<id>&limit=<n>` | למתחזק: כמו הרשימה, ועם כל חבילה גם התוכן שלה (`package`), עד 50 בבקשה |
| `GET /v1/packages/<id>` | למתחזק: החבילה כמו שהגיעה |
| `GET /` | האתר (למטה). הכתובת הישנה `/admin` מובילה אליו |

הבקשות של המתחזק נושאות `Authorization: Bearer <FEEDBACK_ADMIN_TOKEN>`. האתר והכתובת הציבורית לא צריכים קוד.

## האתר

הכתובת `https://pardes-feedback.<תת-הדומיין>.workers.dev/` היא "מאגר החיפושים הפתוח": אתר לכל משתמשי תוכנות הספרייה
התורנית, לא של תוכנה אחת. כולם רואים בו, בלי קוד, את מה שהנתונים מסתכמים בו:
- **סיכום:** כמה חיפושים, דירוגים, שולחים ושורות בצורת הדף; כמה מהתוצאות שדורגו היו רלוונטיות; החבילות בכל יום ב־30
  הימים האחרונים; חלוקת הדירוגים; הדירוגים של כל מודל חיפוש; ובאיזו תוכנה נעשו החיפושים (פרדס, ומזית ואוצריא דרך
  [הכלי לשליחת נתוני חיפוש](https://github.com/efrul/semantic-query-telemetry)).
- **צורת הדף:** טבלאות עם חיפוש ומיון, והורדה כ־CSV.
- **חבילות:** כל חבילה כפי שהיא בכתובת הציבורית, והשולחים שמחקו את מה ששלחו.
- **העלאה:** גוררים לדף או בוחרים קובצי חבילה (`pardes-feedback-….json`) ששמרו מהכלי לשליחת נתוני חיפוש, מפרדס למחשב
  או מכל תוכנה שכותבת את הפורמט, והאתר שולח אותם ל־`POST /v1/packages` כמו האפליקציה. חבילה גדולה מ־900,000 בתים מתחלקת
  לחלקים כמו באפליקציה, קובץ יכול להכיל גם רשימה של חבילות, וכשמגבלת הקצב נגמרת האתר מחכה וממשיך. קובץ שאינו חבילה של פרדס
  נדחה עם הסבר.

**כניסת מנהל:** בכפתור "כניסת מנהל" נותנים את קוד המנהל (הערך של `FEEDBACK_ADMIN_TOKEN`), והאתר קורא את החבילות כמו שהגיעו
מהכתובות של המתחזק, כמו `fetch.py`. אז מופיעים גם החיפושים הנפוצים, ולשוניות החיפושים והדירוגים עם טבלאות והורדה כ־CSV. גם
במצב מנהל לא מוצג מזהה של שולח. עם "לזכור במכשיר הזה" הקוד נשמר בדפדפן; בלי זה, הוא נשכח כשסוגרים את הלשונית.

לכל לשונית יש כתובת משלה (למשל `/#daf`), כדי שאפשר יהיה לשלוח קישור ישר אליה. הדף עצמו לא מכיל נתונים: הוא קורא אותם
מ־`GET /v1/public/packages`, ובמצב מנהל מ־`GET /v1/packages?bodies=1`. חבילה שהועלתה פעמיים נספרת פעמיים ברשימת החבילות,
אבל לא מכפילה את החיפושים והדירוגים, כי כל שורה נספרת פעם אחת. כך גם אותם נתונים שנשלחו שוב עם מזהה שולח חדש: דירוג, חיפוש
או סימון זהים עד לאלפית השנייה הם של אדם אחד, ונספרים פעם אחת.

**חבילה שלא צריכה להיות שם** (למשל העלאה של מישהו שאינה משוב אמיתי): קוראים אותה עם קוד המנהל ב־`GET /v1/packages/<id>`,
לוקחים ממנה את `sender`, ומוחקים את כל מה שאותו שולח שלח ב־`DELETE /v1/senders/<sender>`.

**הבטיחות:** כל טקסט שהגיע בחבילה מוצג כטקסט בלבד, ולא כקוד. ה־CSP של הדף לא מריץ שום סקריפט חוץ מ־`src/site/app.js`,
לא פונה לשום כתובת חוץ מהשירות עצמו (גם הגופן מוגש מה־Worker), ולא מאפשר להציג את הדף בתוך מסגרת של אתר אחר.

**העיצוב:** ניטרלי, בלי המיתוג של אף תוכנה, כמו מפתח של ספרייה: כותרת גדולה בגופן עברי מסורתי, המספרים העיקריים בין קווים
דקים, החיפושים הנפוצים כרשימה ממוספרת, וחלקים שמופרדים בקווים במקום מסגרות. צבע אחד, תכלת, וגרף בגוון אחד שנבדק לניגודיות
במצב בהיר וכהה. נבדק מול הסקיל `frontend-design` של Anthropic. הגופן של הכותרות והחיפושים הוא Frank Ruhl Libre, מוקטן
לעברית, לספרות ולסימני הפיסוק (`src/site/display.woff2`, ברישיון SIL Open Font License 1.1, ראו
`src/site/OFL-Frank-Ruhl-Libre.txt`).

**קוד המנהל** (הערך של `FEEDBACK_ADMIN_TOKEN`) נדרש לכתובות של המתחזק, ש־`fetch.py` קורא, ולכניסת המנהל באתר. ממנו נגזר גם
המפתח של המזהים האטומים, כך שהחלפת הקוד מחליפה גם אותם. אם הוא אבד:
1. בוחרים מחרוזת אקראית ארוכה חדשה.
2. שמים אותה בסוד `FEEDBACK_ADMIN_TOKEN` ב־GitHub.
3. מריצים את Actions › Feedback service › Run workflow.
4. משנים גם את `PARDES_FEEDBACK_ADMIN_TOKEN` אצלכם, בשביל `fetch.py`.

**מגבלות:**
- חבילה עד 1,000,000 בתים. האפליקציה שולחת חבילה גדולה בחלקים של עד 900,000 בתים, וכך גם ההעלאה באתר.
- עד 200 חבילות ביום לשולח.
- עד 20 חבילות או מחיקות בדקה מכתובת אחת.
- עד 300 קריאות בדקה של האתר (`GET /v1/public/packages`) מכתובת אחת.

## ההקמה, פעם אחת

1. **חשבון Cloudflare:** ‏`dash.cloudflare.com/sign-up`, דוא"ל וסיסמה, ואישור בקישור שנשלח בדוא"ל. החינמי מספיק: 100,000 בקשות
   ביום ו־5GB ב־D1. אין צורך בדומיין.
2. **שם החשבון:** כברירת מחדל הוא הדוא"ל ("…'s Account"). כדאי לשנות אותו לשם שלא מזהה אתכם: Configurations › Account Name ›
   Change Name.
3. **תת־הדומיין של workers.dev:** ב־Workers & Pages, ליד Your subdomain. הוא חלק מהכתובת שהאפליקציה שולחת אליה. אם הוא מזהה
   אתכם, או שעוד אין כזה, בוחרים ב־Change שם שלא מזהה.
4. **API token:** ‏Manage Account › API Tokens (או My Profile › API Tokens) › Create Token › התבנית Edit Cloudflare Workers. לתבנית
   מוסיפים שורה: Account › D1 › Edit. אחר כך Continue to summary › Create Token. הטוקן מוצג פעם אחת בלבד.
5. **מזהה החשבון:** ב־Workers & Pages, תחת Account Details, ליד Account ID.
6. **שלושה סודות** ב־Settings › Secrets and variables › Actions של הריפו:
   - `CLOUDFLARE_API_TOKEN`: הטוקן.
   - `CLOUDFLARE_ACCOUNT_ID`: מזהה החשבון.
   - `FEEDBACK_ADMIN_TOKEN`: מחרוזת אקראית ארוכה, שגם נשמרת אצלכם, כי `fetch.py` צריך אותה.
7. **פרסום:** Actions › Feedback service › Run workflow. הוא בודק את ה־Worker, יוצר את המסד בפעם הראשונה, מחיל את
   ה־migrations, מפרסם, וקובע את הטוקן. שם החשבון, הדוא"ל שבו, תת־הדומיין ומזהה המסד מוסתרים ביומן.
8. **הכתובת:** ב־Workers & Pages › pardes-feedback מופיעה `https://pardes-feedback.<תת-הדומיין>.workers.dev`. כשפותחים אותה
   בדפדפן, מופיע האתר. את הכתובת שמים בסוד `PARDES_FEEDBACK_URL`, ומשם היא נכנסת לגרסאות של פרדס
   למחשב (`desktop-release.yml`). גרסה שנבנתה בלי הכתובת לא שואלת ולא שולחת, ורק שומרת משוב לקובץ.

אחרי זה, כל שינוי ב־`feedback-service/` שנכנס ל־main מתפרסם לבד. שינוי במסד נכנס כ־migration חדש ב־`migrations/`.

## מקומית

```
npm ci
npm test
npx wrangler d1 migrations apply pardes-feedback --local
echo 'ADMIN_TOKEN=local' > .dev.vars
npx wrangler dev
```

`npm test` מריץ את הבדיקות ב־Miniflare, סביבת ההרצה של Cloudflare. האתר המקומי נמצא ב־`http://127.0.0.1:8787/`. מול ה־Worker המקומי בונים את האפליקציה עם
`-Pfeedback.url=http://127.0.0.1:8787` (או `feedback.url` ב־`local.properties`), ומריצים את `fetch.py` עם
`--url http://127.0.0.1:8787`.
